# MacroPad

Native macOS menu bar companion for Mars Gaming MSD-TWO / HANVON UGEE CS06 (0B00:1001). Uses IOKit HID in userland; no vendor app or driver required.

Build with `tools/build.sh`, then open `.build/MacroPad.app`. Configuration is saved in `~/Library/Application Support/MacroPad/bindings.json`. If `bindings.json` or `appearance.json` can't be read, MacroPad copies it to a timestamped `*.malformed-<UTC time>.json` backup in the same folder, then writes default settings and shows an alert. You can save a copy elsewhere or open Finder with the backup selected. If the backup can't be created, the original is left untouched. MacroPad then runs with default settings until the file is fixed or moved and the app is restarted.

On macOS 13 or later, toggle **Launch at Login** in the menu bar menu to register or remove MacroPad as a login item. If macOS requires approval, the menu shows an approval-required state and selecting it opens System Settings → Login Items. Registration errors appear in an alert. Move the app to its permanent location (for example, `/Applications`) before enabling this option.

Select **Scenes → Scene N** in the menu bar menu to switch scenes without opening the configuration window. The active scene is checked; the list updates whenever the menu opens.

Large dial defaults: clockwise raises the current default audio output by 2%, counterclockwise lowers it, and press toggles mute. Core Audio controls depend on the output device exposing writable volume/mute properties; HDMI and some interfaces may not. Errors appear in the configuration window.

Each mapped control supports volume, mute, a recorded key combination, application launch, inline AppleScript (via osascript), or a shell script (via zsh). Shortcut recording captures one combination, not a timed sequence. A Keystroke action does nothing until a shortcut has been recorded. Keystroke playback requires macOS Accessibility permission. AppleScript controlling other apps may require Automation permission. Scripts run serially and should terminate promptly.

Actions are grouped into Media & Audio, Mac Display, MSD-TWO Display, Scenes, and Keyboard & Automation submenus. Media & Audio includes separate Previous track, Play/pause, and Next track actions that send the command directly to the current Now Playing app through macOS's MediaRemote framework (as Control Center does), so they need no Accessibility permission (user-verified on macOS 26.6). MediaRemote is a private framework; if it is unavailable, MacroPad falls back to posting media-key events, which does require Accessibility permission. Choose these actions instead of recording the keyboard's media keys. Ordinary F1–F12 shortcuts can still be recorded using Fn when required by the keyboard settings. Existing volume and brightness actions retain their behavior.

Media-key encoding checks (without posting events or controlling playback): `swiftc -module-cache-path .build/module-cache Sources/MediaKey.swift tools/test-media-keys.swift -o .build/test-media-keys && .build/test-media-keys`. Actual media-player response requires manual verification.

Configuration recovery checks (in a temporary folder): `swiftc -parse-as-library -module-cache-path .build/module-cache Sources/ConfigurationFile.swift tools/test-configuration-file.swift -o .build/test-configuration-file && .build/test-configuration-file`.

Hardware mappings are in `captures/control-map.md`. LCD key 1 reporting was verified after an image upload. All six LCD keys are configurable using the documented codes 1–6; the user has confirmed that all six keys work and images appear in the correct order. Any number of automatically numbered scenes can hold separate actions, artwork, and device backgrounds for those six screen keys. Create, select, and delete scenes in the configuration window; background controls sit directly above the scene dropdown and apply to the selected scene. Assign the `Next scene` and `Previous scene` actions to any hardware controls to cycle through them. Scene navigation wraps around. Other hardware mappings remain shared between scenes. Existing `bindings.json` configurations and the prior shared background setting are migrated to the first scene on launch. Previously named scenes retain their actions and artwork and are displayed by number. The app uploads numbered 64×64 JPEG images on connection and sends a periodic heartbeat. Vendor software has been extracted only into `/private/tmp/msd-package-inspection` for static inspection; it has not been installed or executed. Protocol references: https://github.com/4ndv/opendeck-akp03, https://github.com/4ndv/mirajazz, and https://github.com/tommybobb/crabdeck. These explicitly identify MSD-TWO support; our app implements the wire protocol directly.

The configuration window presents a clickable device illustration with an action editor for the selected control. Script fields use plain text with smart substitutions disabled and standard clipboard and undo shortcuts. The bundle identifier is `nl.theredhead.msd-two`.

The window uses a native unified toolbar for the title, device subtitle, and live connection status, keeping them outside the settings content area. macOS supplies the toolbar's current system appearance, including Liquid Glass on supported versions.

Validation: native executable compiled and ad-hoc signed; device selection visually checked. User confirmed dial volume control, AppleScript execution, and copy/paste. Shortcut playback, application launching, shell scripts, and mute still require end-to-end verification. This is an initial implementation, not a completed device protocol.

Appearance: each scene has its own device background, defaulting to black, with a local-image or DuckDuckGo search picker and 4:3 drag/zoom crop. LCD application actions use their app icon automatically; other actions, including Next scene and Previous scene, use a symbol or a chosen local/search image with a square crop. Custom crops are copied into Application Support/MacroPad/Images and persisted with the configuration. Rendered key and background images are cached, and rapid edits or scene changes are combined into one device update of the latest state. A frame is only sent when all six keys and the background render successfully. Images update without reconnecting.

Drag an application from Finder onto a button or dial gesture in the device illustration to assign Open application and restore its automatic app icon. Drop an image onto a screen button to change only its artwork, or onto the background row to change the selected scene's wallpaper. Square button images and 4:3 backgrounds apply immediately; other aspect ratios open the crop editor. Images are copied into Application Support, and pending drops/crops remain associated with the scene where they started even if you switch scenes. Drop one item at a time; unsupported files and loading errors appear in the status message. Images larger than 30 MB or 100 megapixels are rejected, and larger images are downsampled to 4096 pixels on their longest side before cropping. Search results are downloaded with the same 30 MB cap, enforced while the image downloads. Only one artwork window is open at a time; opening another closes the previous one. Drop targets highlight while hovering.

Appearance validation: DuckDuckGo results and result selection verified in the app, crop zoom and cancellation checked, square/4:3 crop output dimensions and key/background image dimensions checked. User confirmed the raw RGB565 black background and all four inset calibration edges on 64×64 tiles. Non-black wallpaper color/orientation still needs physical verification. The background transfer currently uses an empirical 500 ms settling interval before key uploads.

Artwork compositing checks: `swiftc Sources/Artwork.swift tools/test-artwork.swift -o .build/test-artwork && .build/test-artwork` (use `-module-cache-path .build/module-cache` in a restricted environment). Tests cover PNG alpha preservation through composition and final JPEG tile dimensions. Icons are flattened over wallpaper crops using a regular 3×2 layout; exact tile-to-wallpaper registration still needs device calibration.

Brightness actions are separate for the Mac display and MSD-TWO. Each has up/down actions in 5% increments. The Mac automatic-brightness action toggles native ambient-light compensation. The MSD-TWO adaptive action follows the built-in Mac display's brightness (or the primary screen if there is no built-in screen), polling once per second; manual pad adjustments disable following. Pad brightness and following preference are saved. Native Mac control uses dynamically loaded DisplayServices APIs; unsupported displays report an error. No DDC support for third-party external monitors is implemented.

Brightness validation: build passes; native Mac brightness and automatic-brightness state read successfully on the development Mac. Physical dial-driven changes and toggle behavior still require user verification.
